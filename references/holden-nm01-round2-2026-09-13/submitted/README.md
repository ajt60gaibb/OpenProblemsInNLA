# NM-01 — second research round

**Status: additional partial results, not a complete solution.**

This package continues the first-round work on the rational-input minimum-volume decision problem under the repository's exact sufficient-scattering promise. It does not provide a uniform polynomial-time solver or a promise-preserving hardness reduction. The original archive is included unchanged under `previous/`.

Start with **`paper/nm01_round2.pdf`**. Its LaTeX source is included. The proofs distinguish the repository's weak orthogonal-cone SSC condition from the stronger dual-boundary condition.

## New mathematical results

**Conditional exact factor recovery.** On the strong-SSC subclass, a polynomial-time exact-decision oracle would give exact hidden-factor recovery up to permutation. Theorem 2.3 uses `O(r^4)` exact-value queries of polynomial bit length and polynomial additional bit work. Rational threshold bisection simulates value queries, including equality. The informative identity is

`F(v) = sqrt(mu_0 / mu_(e+delta*v)) = product_i (1 + delta*v^T*T_i)`.

Projective transformations, not ordinary affine transformations, supply these values. Polynomial interpolation and univariate rational factorization recover the hidden columns. A polynomial-bit perturbation bound keeps the queries inside strong SSC. **This is an oracle reduction, not an implementation of the missing oracle.**

**Weak-SSC diagonal rigidity.** Theorem 3.1 gives an explicit rational rank-three weak-SSC input for which a positive diagonal reweighting preserves SSC1 only when it is scalar. Theorem 3.2 proves that every projective perturbation along a specified line with `0 < |t| <= 1/1000` lies outside the entire original promise, not merely outside the inherited factorization. A twenty-triple exact interval certificate proves the latter claim. Thus the strong-SSC reduction cannot silently be applied to the full repository promise.

**An all-degree obstruction to one SOS route.** For every total degree `D >= 2`, Theorem 4.5 constructs a rational, strongly scattered rank-three matrix of polynomial encoding length in `D` for which `1 - ||q||^2` has no degree-`D` representation in the full preordering generated by the input linear inequalities on `e^T q = 1`. This formulation allows all products of inequalities, so the result also excludes the corresponding quadratic module. A rational separating functional gives a nonzero finite-precision gap. The proof uses a contact-count argument and uniformly controlled rational perturbations; it is not extrapolated from the finite tests.

**Standard dense hierarchy sizes.** Padding yields strongly scattered inputs with `r = 2D+1` and `n = 2r-3` that require degree above `D`. Standard full-monomial SOS levels then have matrix dimensions exponential in `r`. This excludes that specific dense certificate strategy, not all SDPs, sparse lifts, or polynomial-time algorithms. These constructed inputs have known optimal value one, so they are not hardness reductions for NM-01.

## Reproduce the checks

The tested environment is Python 3.13.5 and SymPy 1.14.0, recorded in `verification/environment.json`. The SOS checkers use only the Python standard library. The complete suite, projective recovery, and interval-certificate regeneration additionally require SymPy.

From this directory:

```sh
python -m pip install -r requirements.txt
python code/check_manifest.py
python code/test_round2.py --full --report /tmp/nm01-round2-tests.json
python code/sos_obstruction.py --verify certificates/sos_degree8_strong.json
python code/verify_raw_sos.py certificates/sos_degree6_strong.json
python code/rigidity.py --verify certificates/weak_rigidity.json
python code/projective_recovery.py --rank 4 --verify certificates/projective_rank4.json
```

Omitting `--full` explicitly skips the degree-eight test. That is not a complete run. JSON rationals are integers or strings such as `"3/4"`; binary floating-point entries are rejected by the exact arithmetic reader.

`projective_recovery.py` implements the polynomial-query reconstruction procedure, but its demonstration `FacetValueOracle` is **exponential** in variable rank. The recovery procedure receives only the data, perturbation scale, and value callback. A separate test observer validates the strong-SSC promise on every demonstration query without passing the generating factors to the recovery procedure. Rank-three and rank-four runs use 24 and 73 distinct queries and recover the exact generating factors up to permutation.

The frozen SOS certificates exclude degrees four, six, and eight. They verify respectively 256, 4,096, and 65,536 rational positive-definite quotient localizing matrices: **69,888 matrices across the three certificates**. A separate full-monomial verifier also checks degrees four and six without the quotient reduction. The degree-four and degree-six logs include all rational LDL pivots. The degree-eight log gives aggregate counts and the minimum pivot; every pivot is regenerated by the checker.

The full new suite passed all **23 test methods** with no errors, failures, or skips. All **16 original test methods** were rerun as a separate regression check. Actual logs and the clean-extraction reproduction report are in `verification/`. These checks are reproducible computational evidence, not an independent mathematical audit or formal proof-assistant verification.

## File map and cautions

`paper/` contains the report and source; `code/` the exact programs; `certificates/` nine JSON instances/certificates; `verification/` actual logs; `sources/` source locators and research-scope notes. `previous/NM01_partial_results.zip` preserves the original work byte for byte. `MANIFEST.sha256` covers every delivered file except itself. The manifest checker also tolerates newly generated Python caches but detects changes to listed files.

To rebuild the PDF, run `pdflatex -interaction=nonstopmode -halt-on-error nm01_round2.tex` twice from `paper/`. Standard LaTeX packages listed in the source are required. Font files are not included.

One exploratory degree-eight scale choice failed exact certification and is explicitly excluded from the results; see `sources/RESEARCH_LOG.md`. No numerical optimizer's status is used as a proof. No repository files were changed. No broad novelty or priority claim is made. **The missing polynomial-time value oracle and the full original-promise decision question remain unresolved by this package.**
